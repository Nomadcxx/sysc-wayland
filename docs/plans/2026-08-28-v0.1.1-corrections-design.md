# sysc-wayland v0.1.1 Corrections Design

## Goal

Make core binding generation reproducible, correct array request framing, and publish qualification
commands that build the generated consumer packages.

## Scope

- Replace the vendored Wayland 1.26 XML with the exact Wayland 1.24 XML used by the released binding.
- Regenerate `client/client.go` so its source comment names the vendored XML while preserving its API
  and dispatch behavior.
- Encode request arrays as a four-byte payload length followed by a padded payload.
- Write xdg-shell, layer-shell, fractional-scale, and viewporter bindings into separate package
  directories in the qualification instructions.
- Update release wording and use `v0.1.1` in consumer commands.

The patch does not add protocols, change connection ownership, or adopt the Wayland 1.26 API.

## Implementation

`protocols/wayland.xml` becomes the single source for the v0.1.1 core binding. `go generate ./client`
must reproduce the checked-in binding without a diff.

The scanner will calculate both the raw array length and its padded wire length. Generated requests
will allocate and advance by four bytes plus the padded length; `client.PutArray` will continue writing
the raw payload length and bytes into the zero-filled buffer.

README qualification commands will create one directory per generated package. Layer-shell will import
the generated xdg-shell package at its matching module path.

## Verification

- A scanner regression fixture must fail before the array fix and pass after it.
- Core generation must leave `client/client.go` unchanged.
- The race suite, vet, and build must pass.
- Two clean temporary modules must produce byte-identical protocol bindings and compile them.
- A live Niri probe must complete two roundtrips without a protocol error.
